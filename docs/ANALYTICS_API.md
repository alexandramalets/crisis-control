# API интеллектуального микросервиса

Отдельный процесс и контейнер `analytics-service`. Алгоритмы не размещаются во frontend и не дублируются в основном backend. Сервис не подключается к PostgreSQL: принимает числовую матрицу наблюдений и возвращает результаты процедур.

Базовый URL: `http://<узел>:8001`. Префикс контракта: `/analytics/v1`.

Клиент браузера этот API не вызывает. Единственный потребитель — серверное приложение через адаптер `backend/app/integrations/analytics_client.py`. Пользовательские операции: `POST /api/v1/analyses` и связанные пути (см. `backend/README.md`).

Интерактивная спецификация: `GET /analytics/docs` (OpenAPI: `GET /analytics/openapi.json`).

## Доступ

| Заголовок | Кто вызывает | Назначение |
|---|---|---|
| `X-Service-Key` | только серверное приложение | Совпадает с `ANALYTICS_SERVICE_KEY` (не менее 32 символов) |

`GET /analytics/v1/health` и документация открыты. Все остальные операции требуют ключ. Неверный или отсутствующий ключ → `401`.

Логи содержат `request_id`, имя процедуры и статус. Значения показателей и сервисный ключ в журнал не пишутся.

## Общая форма данных

Тело POST-запросов — JSON.

```json
{
  "request_id": "optional-id",
  "random_state": 42,
  "periods": ["2020-01", "2020-02"],
  "indicators": [
    {
      "code": "Profit",
      "values": [10.0, 12.5],
      "impact_direction": "higher_better",
      "weight": 1.0,
      "lower_bound": 0,
      "upper_bound": 100
    }
  ]
}
```

- `periods` и `values` одной длины; коды уникальны; периоды не повторяются.
- Пропуск кодируется JSON `null`.
- `impact_direction`: `higher_better` | `lower_better` | `neutral` (для сводной оценки).
- Несовпадение длин → `422`, код `invalid_data`.

Ответ процедуры:

```json
{
  "status": "ok",
  "message": "…",
  "warnings": [],
  "result": {}
}
```

`status`: `ok` | `skipped` | `error`. При нехватке наблюдений сервис не подставляет искусственные числа: `skipped` и `result = null` (кроме оценки, где явно возвращается «Недостаточно данных»).

## Операции

### GET `/analytics/v1/health`

Состояние процесса и версии pandas, NumPy, SciPy, scikit-learn, statsmodels.

### GET `/analytics/v1/capabilities`

Список процедур, значения по умолчанию, ограничения. Требует ключ.

### POST `/analytics/v1/validate`

Проверка полноты, пропусков, константности. Если пригодных рядов нет — сообщение «Недостаточно данных».

### POST `/analytics/v1/anomalies`

Статистический метод: медиана и MAD (согласованный с нормальным законом, эквивалент формулы \(0{,}6745\cdot(x-\mathrm{median})/\mathrm{MAD}\)).

Параметры: `method` (`robust_z` по умолчанию или `zscore`), `threshold` (по умолчанию 3), `min_observations` (по умолчанию 6).

Если наблюдений меньше минимума — `skipped`. Если MAD = 0, используется классическая z-оценка (предупреждение). Если и σ = 0 (постоянный ряд) — аномалий нет.

Элемент аномалии: `indicator`, `period`, `value` (факт), `baseline` (опора: медиана или среднее), `deviation`, `score`, `direction` (`above` | `below`), `method`.

### POST `/analytics/v1/correlation`

Матрица Пирсона попарно. Пропуски исключаются попарно. Константный столбец → коэффициент `null` и примечание. При числе совместных точек меньше `min_observations` (по умолчанию 4) пара пропускается.

Поле `interpretation` фиксирует: корреляция не есть причинность.

### POST `/analytics/v1/clustering`

k-средних после `StandardScaler`. Параметры: `k` (число или `"auto"`), `k_min`, `k_max`, `random_state`.

При `k=auto` число кластеров выбирается по максимуму силуэта. Силуэт считается, если кластеров ≥ 2 и наблюдений больше k.

Ответ: `members` (период → номер кластера), `clusters` (размер и центры в исходном и масштабированном масштабе), параметры алгоритма (`n_init=10`, scaler, k), метрики (`silhouette`, `inertia`, `silhouette_by_k`).

Номер кластера **не** именуется кризисным. Интерпретация — только по центрам и направлению влияния показателей, вне этой процедуры.

### POST `/analytics/v1/forecast`

Простое экспоненциальное сглаживание (`statsmodels`, `SimpleExpSmoothing`). Параметр `horizon` (1…24).

Ответ по каждому ряду: `history` (исходные значения, пропуски как `null`), `forecast` (даты будущих периодов, точечная оценка, при ненулевой дисперсии остатков — интервал ±1,96σ), `method`.

Минимум 4 конечных наблюдения. Иначе `skipped` без прогнозных точек. Внутренняя интерполяция пропусков используется только для оценки модели и отражается в `warnings`; в `history` остаются исходные значения.

### POST `/analytics/v1/assessment`

Сводная оценка состояния \(C = 100 \sum_j w_j q_j\), \(C \in [0; 100]\). Высокий балл — устойчивее, низкий — больше признаков риска.

\(q_j\) — нормализация последнего наблюдения в диапазоне порогов (`lower_bound`/`upper_bound`) или min–max ряда, с учётом `impact_direction`. Веса нормируются; при отсутствии весов — равные.

Если периодов < 3 или ни один показатель не нормализуется: `status_label` = «Недостаточно данных», `score` = `null`.

### POST `/analytics/v1/analyze`

Конвейер. Поле `procedures` задаёт набор (`validate`, `anomalies`, `correlation`, `clustering`, `forecast`, `assessment`). По умолчанию выполняются все. Ошибка одной процедуры не отменяет остальные.

## Ошибки HTTP

| Код | Когда |
|---|---|
| 401 | нет или неверный `X-Service-Key` |
| 404 | неизвестный путь |
| 422 | схема Pydantic или несовпадение длин рядов |
| 500 | непредвиденный сбой (без значений показателей в тексте) |

Тело: `{ "error": { "code", "message", "details" } }`.

## Замечания по интерпретации

- Корреляция описывает статистическую связь, не причину.
- Кластеры нумеруются 0…k−1 без ярлыков «кризис / норма».
- Оценка 0–100 интерпретируема через вклады показателей (`components[].explanation`).
